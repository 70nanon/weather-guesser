# Location Mode アップデート予定

ステータス: **計画のみ。このドキュメントでは実装しない。** 追記しながら育てる。

目的は Location Mode を日本国内向けの推理ゲームとして遊びやすくすること。一括実装はしない。下のチケットを、前提が満たされていれば好きな順で進める。

---

## 現在の関連実装

Location Mode は `src/modes/LocationMode.tsx`、Forecast Mode は `src/modes/ForecastMode.tsx`。状態・採点・天気取得は分かれている。

### 正解地点

- `src/data/targetCities.ts` の `TARGET_CITIES`（46 都市）から `pickTargetCity()` で選ぶ。
- 完全なランダム座標ではない。リストは世界規模で、日本は札幌・東京・那覇の 3 都市だけ。
- 地点名 / 国 / 座標はプレイヤーに出さない。天気取得失敗時は別候補を最大 3 回試す。

### 天気表示

- `fetchWeatherSnapshot()` が現在気温・最高/最低・天気・湿度・降水量・風・気圧・日の出・日の入りを返す。
- `WeatherSnapshotCard` が描画。秘密地点では `place` を渡さない。調査結果では `札幌 / 日本` のように出す。
- 気象項目セットは維持する。

### 調査

- 最大 3 回（`MAX_INVESTIGATIONS`）。
- `InvestigatePanel` で検索し、結果カードは `LocationMode` が縦に積む。
- 日本語検索は `searchLocalCities()` が `TARGET_CITIES` + 追加都市を先に照合し、なければ Open-Meteo geocoding。
- 調査地点は地図に出ていない。
- 調査の検索候補は左側が地点名、右側が「調査する」。`GeoLocation.country` はあるが候補行では出していない。Forecast の `LocationSearch` は国名を出している。

### 回答・採点

- `AnswerMap` は世界全体（`center=[20,10]`, `zoom=1`）。クリックで回答ピン（オレンジ）。
- 回答後だけ正解ピン（青）と破線。調査ピンはない。
- 距離は `haversineKm`、スコアは `locationScore`（最大 5000、`e^(-km/1500)`）。減衰 1500km は世界向け。調査回数ボーナスは 0。

### Forecast との接点

- タブ以外は独立。
- `searchLocations()` / `searchLocalCities()` は共通。`TARGET_CITIES` を日本だけにすると、予報の日本語世界都市検索がローカルヒットしなくなる。

## LM-1 調査候補を「地点名 / 国名」表示にする

前提: なし

### やりたいこと

調査の検索ヒットを、調査結果カードと同じく `札幌 / 日本` の形で出す。国名がないと、同名地点や海外都市を選びにくい。

### 現状

`InvestigatePanel` の候補行は `loc.name` と、右側の「調査する」（取得中は「取得中…」）。国名スロットをアクション文言で使っている。
Forecast の `LocationSearch` はすでに `name` と `country` を分けて出している。

### 方針

- 主ラベルを `{name} / {country}` にする。国名が空なら地点名だけ。
- 「調査する」は残す（ボタン全体が調査アクション、または右端の小さな表示）。
- データは現行の `GeoLocation.country` で足りる。API / カタログの追加は不要。
- 表示用の小さなヘルパー（例: `formatPlaceLabel(name, country)`）を切ると、候補行と `WeatherSnapshotCard` で揃えやすい。必須ではない。

### 対象ファイル

- `src/components/InvestigatePanel.tsx`（必須）
- 任意: 共通ヘルパー、Forecast の `LocationSearch` を同じ表記に寄せる

### 完了条件

- 候補に国名が見える（調査結果カードと同じ読み方）
- 「調査する」の意味が残る
- 検索・調査の動作は変わらない

## LM-2 問題と調査結果を折りたたみまたはタブで切り替える

前提: なし

### やりたいこと

モバイル幅（390px 前後）では、秘密地点の天気と調査カードが縦に長く、スクロールしないと比較できない。問題と調査結果を同じ画面感覚で切り替えられるようにする。

### 現状

`LocationMode` が「現在の天気」→ 調査パネル → 調査カード 1〜3 → 地図、の順で積んでいる。カードの中身は同じ `WeatherSnapshotCard`。

### 方針（実装時にどちらか選ぶ）

タブを第一候補にする。項目の並びが同じなので、問題 / 調査1 / 調査2 / 調査3 を切り替えると比較しやすい。

- タブ: 常に 1 枚だけ開く。未調査のタブは出さない（または disabled）。
- 折りたたみ: 「問題」をデフォルトで開き、調査カードは閉じておいて見出し（地点名）だけ見せる。複数同時オープンも可。

共通ルール:

- 調査パネル（回数・検索）と地図は、比較 UI の外に置く。たたんでも調査や回答ができなくならないようにする。
- 気象項目は今のまま。比較しやすくするための見せ方の変更だけ。
- デスクトップで横並びにするかは任意。モバイルを優先する。

### 対象ファイル

- `src/modes/LocationMode.tsx`
- `src/App.css`
- 必要なら小さな `WeatherCompareTabs` などのコンポーネント

### 完了条件

- 390px 幅で、問題と直近の調査を大きくスクロールせず見比べられる
- 調査 0 回でも問題の天気は見える
- 地図と検索は使える

## LM-3 正解リストと検索カタログを分離する

前提: なし。**LM-4 の前提。** 出題を日本だけにする前に、Forecast の検索を守るための土台。

### やりたいこと

Location の正解配列と、両モード共通の検索カタログを別にする。

### 現状

`searchLocalCities()` が `TARGET_CITIES` を読んでいる。`ROMAJI_ALIASES` は世界都市の id に紐づいている。

### 方針

1. 検索カタログ = 正解リスト + 検索専用エントリ（世界都市の日本語・ローマ字など）
2. `pickTargetCity()` は正解リストだけを見る
3. aliases を検索専用側へ寄せ、正解リスト差し替えで id が変わっても世界都市検索が残るようにする

このチケット単体では、正解はまだ世界 46 都市のままでよい。構造だけ分ける。

### 対象ファイル

- `src/data/searchCities.ts`
- `src/data/searchCities.test.ts`
- 必要なら `src/data/targetCities.ts`（export の切り方）

### 完了条件

- 東京・札幌・大阪の日本語検索が当たる
- ロンドン等の日本語世界都市検索が当たる
- Location の出題ロジックはまだ変えない

## LM-4 正解地点を日本国内リストにする

前提: **LM-3**

### やりたいこと

正解を日本国内の安定した都市・観測可能地点から選ぶ。完全なランダム座標にはしない。

### 方針

- `TARGET_CITIES` を日本のみにする。`country` は `'日本'`。
- 都道府県庁所在地を基本（約 47）。北海道〜沖縄をカバーする。
- 道内の幅が欲しければ札幌に加えて旭川・釧路・函館。沖縄は那覇、任意で石垣。
- `EXTRA_SEARCH_CITIES` の大阪・名古屋などは県庁所在地に含まれるので正解側へ統合してよい。
- 「安定」= よく知られた都市の固定座標。気象庁コードは持たない。Open-Meteo は緯度経度だけで足りる。

データ形式は現行の `TargetCity` のまま。置き場所も `src/data/targetCities.ts`。

### 対象ファイル

- `src/data/targetCities.ts`
- `src/data/targetCities.test.ts`（すべて日本、id 一意、件数、地方の偏り）
- `src/data/searchCities.test.ts`（日本化後も世界都市の検索専用が残ること）

### 完了条件

- Location の正解が日本のみ
- Forecast のルールは変わらない
- 日本語の国内都市検索と、検索専用の世界都市が両立する

### 注意

- この時点では地図はまだ世界全体でも動く。見た目の日本化は LM-5。
- スコア式はまだ世界向け。国内向け採点は LM-7。

## LM-5 地図の初期表示を日本全体にする

前提: **LM-4**（世界出題のまま日本地図だけにすると説明と矛盾する）

### やりたいこと

回答用地図を、最初から日本全体が見える状態で開く。北海道から沖縄が切れないこと。

### 方針

- 中心おおよそ `[37.5, 137.0]`、`zoom` 5 前後。または bounds（北緯 24–46、東経 123–146 程度）で `fitBounds`。
- 地図ロックは任意。ロックするなら小笠原・石垣が切れないようにする。
- 回答後の、回答ピンと正解ピンへの `fitBounds` は維持してよい。
- 文言を日本向けにする: `App.tsx` の「世界のどこか」、`LocationMode` の「世界地図」、`README.md`。

### 対象ファイル

- `src/components/AnswerMap.tsx`
- `src/modes/LocationMode.tsx`
- `src/App.tsx`
- `README.md`

### 完了条件

- ラウンド開始時に日本列島が画面に入っている
- 気象項目は変えない
- Forecast に影響しない

## LM-6 調査地点を地図上に出す

前提: なし。地図が日本になってからの方が自然なので、**LM-5 のあとがおすすめ。** 世界地図のままでも実装できる。

### やりたいこと

調査した最大 3 地点を、回答用地図上に残す。天気と位置関係を見ながら推理できるようにする。正解までの距離・方向・近い/遠いは出さない。

### 方針

- 既存の `investigations` を `AnswerMap` に渡す。新規データは不要。
- 調査ピンは回答ピン（オレンジ）・正解ピン（青、回答後のみ）と色・サイズを変える。番号は `調査1` と揃える。
- 調査ピンから正解へ線を引かない。
- 調査ピンの click は `stopPropagation`。しないと回答座標になってしまう。
- ツールチップは地点名と調査番号まで。距離は書かない。
- 調査のたびに地図を正解へ寄せない。

### 対象ファイル

- `src/components/AnswerMap.tsx`
- `src/modes/LocationMode.tsx`
- `src/App.css`（凡例）

### 完了条件

- 調査した地点が地図に残り、最大 3
- 回答ピンと調査ピンが区別できる
- 距離・方向のヒントが出ない

## LM-7 距離スコアを国内向けにする

前提: **LM-4**。世界出題のまま減衰だけ急にすると、海外同士のずれが極端に低得点になる。

### やりたいこと

距離スコアの考え方は維持（近いほど高得点、最大 5000、大円距離）しつつ、日本列島のスケールに合わせる。現行の減衰 1500km だと、国内の 500–1000km でも点が残りすぎる。

### 現状の目安（減衰 1500km）

- 50km ≈ 4836
- 500km ≈ 3585
- 1000km ≈ 2569
- 3000km ≈ 677

国内の距離感: 東京−大阪 約 400km、東京−札幌 / 福岡 約 800–900km、北海道−沖縄 約 2000km 超。

### 方針案（実装時にテストで微調整）

式は現行と同じ `round(5000 * e^(-km / D))`。`D` だけ変える。

候補: `D = 600` または `800`。

| 距離 | D=800 のとき | 感覚 |
| --- | --- | --- |
| 50km | 約 4700 | ほぼ満点 |
| 200km | 約 3900 | 高得点（隣県〜地方内） |
| 400km | 約 3000 | そこそこ上（東京−大阪級） |
| 800km | 約 1800 | 低め（東京−札幌級） |
| 1500km | 約 770 | 低い |
| 2000km+ | 約 400 以下 | ほぼ外れ |

最大 5000、調査回数ボーナス 0 は維持。`locationScore.test.ts` の距離帯コメントを国内向けに書き換える。

### 対象ファイル

- `src/logic/locationScore.ts`
- `src/logic/locationScore.test.ts`

### 完了条件

- 国内の「近い / 地方違い / 列島の端」で点差がつく
- 計算は React 内の純関数のまま
- Forecast の 100 点スコアは触らない

## チケットを進めるときの注意

- 1 チケット ≈ 1 PR を目安にする。LM-5 と LM-6 のように地図が近いものは、前提を満たしていればまとめてもよい。
- LM-3 なしで LM-4 をやると、Forecast の「ロンドン」などが日本語で外れやすくなる。
- LM-4 なしで LM-5 / LM-7 を出すと、出題が世界のまま地図や点が日本仕様になり、遊びとしてちぐはぐになる。
- LM-1 と LM-2 はデータ変更と独立しているので、日本化より先に出してよい。
- ランキング、ログイン、戦績、デイリー、調査回数の変更、気象項目の増減は対象外。
