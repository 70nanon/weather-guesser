# Location Mode アップデート予定（日本国内向け）

ステータス: **計画のみ。このドキュメントの時点では実装しない。**

目的は新機能を増やすことではなく、天気だけを手がかりにした推理を **日本国内** で成立させること。

Forecast Mode と、Location Mode の基本ルール（調査最大 3 回、表示中の気象項目、日の出・日の入り、距離スコア、地図タップで回答）は現状維持する。

---

## 現在の関連実装

Location Mode はすでに `src/modes/LocationMode.tsx` に分離されており、Forecast Mode（`src/modes/ForecastMode.tsx`）とは状態・採点・天気取得関数が分かれている。

### 正解地点

- `src/data/targetCities.ts` の `TARGET_CITIES`（46 都市）から `pickTargetCity()` でランダム選択している。
- **完全なランダム座標ではない。** ただしリストは世界規模で、日本は札幌・東京・那覇の 3 都市だけ。
- 地点名 / 国 / 緯度経度はプレイヤーには出さない。天気取得に失敗したら別候補を最大 3 回試す。

### 天気表示

- `fetchWeatherSnapshot()`（`src/api/openMeteo.ts`）が現在気温・最高/最低・天気・湿度・降水量・風・気圧・日の出・日の入りを返す。
- `WeatherSnapshotCard` が描画する。秘密地点では `place` を渡さないので都市名・国名は出ない。タイムゾーン名も返していない。
- この気象項目セットは今回維持する。

### 調査

- 最大 3 回（`MAX_INVESTIGATIONS`）。
- `InvestigatePanel` で地名検索し、結果カードは名前付きで並べる。
- 日本語検索は `searchLocalCities()`（`src/data/searchCities.ts`）が `TARGET_CITIES` + 日本の追加都市（大阪・名古屋など）を先に照合し、ヒットしなければ Open-Meteo geocoding にフォールバックする。
- **調査地点は地図に出ていない。** 天気カード上の比較だけ。

### 回答・採点

- `AnswerMap` は世界全体（`center=[20,10]`, `zoom=1`）。クリックで回答ピン（オレンジ）。
- 回答後だけ正解ピン（青）と破線を出す。調査ピンはない。
- 距離は `haversineKm`、スコアは `locationScore`（最大 5000、`e^(-km/1500)`）。調査回数ボーナスは 0 のまま。

### Forecast Mode との接点

- モード切替は `App.tsx` のタブだけ。予報のスコア計算・フォームは Location から独立。
- ただし `searchLocations()` と `searchLocalCities()` は両モード共通。`TARGET_CITIES` を日本だけにすると、予報側の日本語検索カタログも変わる。世界都市は Open-Meteo フォールバック（英語名はヒット、日本語名は外れやすい）に落ちる。

## 変更 1: 出題範囲を日本国内に限定する

### 方針

- Location Mode の正解は日本国内のリストからのみ選ぶ。
- 回答地図の初期表示を、北海道から沖縄まで日本全体が見える範囲にする。
- 気象項目（日の出・日の入り含む）は変えない。
- Forecast Mode の出題・採点・明日予想には触れない。

### 対象

| ファイル | 内容 |
| --- | --- |
| `src/data/targetCities.ts` | 正解候補を日本国内だけにする |
| `src/data/targetCities.test.ts` | 全件 `country === '日本'` などを追加 |
| `src/components/AnswerMap.tsx` | 初期 center / zoom、または日本の bounds |
| `src/modes/LocationMode.tsx` | 「世界地図」などの文言 |
| `src/App.tsx` | サブタイトル「世界のどこか」 |
| `README.md` | 場所モードの説明 |

### 再利用

- `pickTargetCity()` はそのまま。渡す配列を日本リストにするだけ。
- `fetchWeatherSnapshot()` / `WeatherSnapshotCard` は触らない。
- 地図コンポーネント自体は Leaflet のまま。初期ビューだけ変える。

### 地図の初期表示案

- 中心おおよそ `[37.5, 137.0]`、`zoom` は 5 前後。
- または `fitBounds` でおおよそ北緯 24–46・東経 123–146 を見せ、北海道と沖縄が切れないようにする。
- 初期表示の変更が主目的なので、地図を日本にロックするかは任意。ロックする場合も北海道・小笠原・石垣が切れない bounds にする。
- 回答後の `fitBounds`（回答ピンと正解ピン）は維持してよい。

### 注意

- コピー（「世界のどこか」「世界地図」）を日本向けに揃えないと、地図だけ日本でも説明が食い違う。
- 距離スコア式は変えない。減衰 1500km は世界向けなので、国内では 500–1000km でも点が残りやすい。今回は仕様どおり現状維持し、必要なら別アップデートで見る。

## 変更 2: 調査した地点を地図上に表示する

### 方針

- 調査した地点を、回答用の同じ地図にマーカーとして残す（最大 3）。
- 天気と位置関係を見ながら絞れるようにする。
- 正解までの距離・方向・近い/遠いは出さない。調査ピンから正解への線も引かない。
- 最終回答ピンとは色・役割を分ける。調査ピンをクリックしても回答座標にしない。

### 対象

| ファイル | 内容 |
| --- | --- |
| `src/components/AnswerMap.tsx` | `investigations` を受け取り、調査マーカーを描画 |
| `src/modes/LocationMode.tsx` | 既存の `investigations` を地図へ渡す |
| `src/App.css` | 凡例（調査ピン） |

### 再利用

- `Investigation`（`location` + `snapshot`）がすでに緯度経度を持っている。新規データ構造は不要。
- 回答ピン（オレンジ）と正解ピン（青、回答後のみ）の `CircleMarker` パターンを流用する。
- 調査カード（`調査1` …）の番号と地図マーカーの番号を揃える。

### 見た目・操作の区別

- 調査: 別色（例: 緑系）、やや小さめ。ツールチップは地点名と「調査1」など。距離は書かない。
- 回答: 現行どおりオレンジ。これが「ここで回答」の対象。
- 正解: 回答後のみ青。調査ピンと正解を線で結ばない。
- 調査マーカーの click は `stopPropagation` する。しないと地図 click 扱いになり、調査地点がそのまま回答ピンになる。

### 注意

- 調査地点の名前を地図に出すのは、プレイヤーが自分で選んだ地点なので問題ない。正解地点の名前は回答前に出さない（現行どおり）。
- 調査 3 回と回答ピンが重なると見づらいので、凡例とサイズ差で区別する。
- 調査のたびに地図を正解へ寄せるような自動移動はしない。

## 変更 3: 安定した日本国内の観測地点リスト

### 現状との関係

「ランダム座標ではなくリストから選ぶ」は **すでにそうなっている**。次の実装でやるのは、世界 46 都市を **日本国内の安定地点リストに差し替える** こと。

Open-Meteo は任意の緯度経度で予報を返せる。ここでの「安定」は、よく知られた都市の固定座標を使い、海上や山中の無名点を出さない、という意味。気象庁の観測所コードは持たない（バックエンドなし、現行 API のまま）。

### データ形式

現行の `TargetCity` を維持する。

```ts
{
  id: number
  name: string
  country: '日本'
  latitude: number
  longitude: number
  aliases?: string[]  // ローマ字・ひらがな。検索用
}
```

配置は現行どおり `src/data/targetCities.ts` がよい。Location Mode の正解と、日本語検索の一次カタログが同じファイルを見ているため。JSON に切り出す必要はない。

`pickTargetCity()` も維持する。

### リスト構成案

都道府県庁所在地を基本にする（約 47）。北海道〜沖縄まで均等で、Open-Meteo も問題になりにくい。

例:

- 北海道: 札幌（必要なら旭川・釧路・函館を追加して道内の幅を出す）
- 東北: 青森・盛岡・仙台・秋田・山形・福島
- 関東: 水戸・宇都宮・前橋・さいたま・千葉・東京・横浜
- 中部: 新潟・富山・金沢・福井・甲府・長野・岐阜・静岡・名古屋
- 近畿: 津・大津・京都・大阪・神戸・奈良・和歌山
- 中国: 鳥取・松江・岡山・広島・山口
- 四国: 徳島・高松・松山・高知
- 九州: 福岡・佐賀・長崎・熊本・大分・宮崎・鹿児島
- 沖縄: 那覇（石垣を足すかは任意。日出・気温差の幅は出る）

`EXTRA_SEARCH_CITIES` の大阪・名古屋・福岡・京都・横浜・神戸・広島・仙台は、県庁所在地リストに含まれるので正解候補へ統合できる。

数の目安は 40〜50。偏りを見るテストとして、地方ごとの件数をざっとアサートしてもよい。

### `searchCities.ts` の扱い（Forecast を壊さない）

`searchLocalCities()` は `TARGET_CITIES` を読んでいる。正解を日本だけにすると、予報モードで「ロンドン」などの日本語世界都市がローカルヒットしなくなる。

実装時の切り分け:

1. Location の正解配列は日本のみ（`TARGET_CITIES`）。
2. 検索カタログは「日本の正解リスト + 世界都市の検索専用エントリ」にする。
3. `ROMAJI_ALIASES` は id 依存なので、世界都市を正解リストから外したら、検索専用側に aliases を移す。

Forecast の検索 UX を今と同等に保つための付随修正であり、Forecast のルール変更ではない。

### 対象

| ファイル | 内容 |
| --- | --- |
| `src/data/targetCities.ts` | 日本の地点リストに置換 |
| `src/data/targetCities.test.ts` | 日本のみ・id 一意・件数 |
| `src/data/searchCities.ts` | 正解リストと検索専用リストを分離 |
| `src/data/searchCities.test.ts` | 東京・札幌に加え、ロンドン等がまだ当たるか |

### 再利用

- `TargetCity` / `pickTargetCity` / `fetchWeatherSnapshot` の失敗時リトライ。
- 調査用の Open-Meteo フォールバック（リスト外の地名）。

## 実装順序

1. **日本の地点リスト** を `targetCities.ts` に入れ、`pickTargetCity` とテストを日本前提にする。`searchCities.ts` を分離して Forecast の日本語検索を維持する。
2. **地図の初期表示** を日本全体にし、Location の文言を直す。
3. **調査マーカー** を `AnswerMap` に足す（凡例・click の伝播止め）。

1 のあとなら、2 と 3 は並行しやすい。マージ単位は 1 PR でまとめてよい（Location の遊びやすさセットだから）。

実装開始後の確認は `AGENTS.md` どおり `npm test` / `npm run lint` / `npm run build` のみ。画面確認はこの計画ドキュメントでは行わない。

---

## 実装時に足すテスト（予定）

- `TARGET_CITIES` がすべて日本で、id が一意、件数が下限以上。
- `pickTargetCity` が日本リストからだけ返す。
- `searchLocalCities('東京'|'札幌'|'大阪')` は現状どおりヒット。
- Forecast 用に、世界都市の日本語（例: ロンドン）が検索カタログに残っていること。
- 既存の予報スコア・距離スコア・風向テストは回帰としてそのまま回す。

地図の見た目そのものの自動テストは、現行どおり必須にしない。
